# 术语表

> 站长、协作 AI（dsh / Claude）、成员报告共用的词表。命名规则：**代码标识符全英文**，
> 注释 / 文档 / 成员可见文案用中文——这里的词是两层之间的对照。

## 站点与角色

| 术语 | 英文/代码 | 含义 |
|---|---|---|
| 成员 | member | 领了 Key 的 Discord 用户（不叫「用户」，避免和管理员混淆） |
| 站长 | owner | 你（Discord id 1110347922597478473），后台维护人 |
| 上游账号 | upstream token / account | 我们的 NovelAI 账号，代成员出图；**Token** 指它的登录凭据 |
| Key | key | 成员手里的 `nai-` 开头密钥，一个成员可有多把 |
| 桥接 | bridge | 官网镜像里我们注入的 `bridge.js`（改 Explore 按钮、上报设备指纹等） |
| 桥接密钥 | bridge secret | 机器人/桥接调 `/self-register/*` 接口的 Bearer 凭据 |
| 镜像 | mirror / nai-app | NovelAI 官方前端的自托管副本（`mirror/nai-app`），成员在它上面生图 |

## 请求与记账

| 术语 | 英文/代码 | 含义 |
|---|---|---|
| 请求日志 | usage_log | 每次请求一行，后台「日志」页 |
| rid | request id | 一次请求的编号，日志页可按前 16 位搜 |
| kind | — | 请求类型：`image` / `image_stream`（流式生图）/ `tags`（标签补全）/ `upscale` / `vibe_encode` / `account`（订阅查询）/ `augment-image`（导演工具） |
| wait_ms | — | **排队等待**毫秒数（网关里排队 + 等账号的时间） |
| dur_ms | — | **上游生成耗时**毫秒数（NovelAI 真正画图的时间） |
| 排队已满 | queue_full | 全站并发槽占满时的 429 拒绝（「最多同时排 N 张」） |
| 槽位 / 并发 | slot / concurrency | 同一时刻允许的请求数：全站出图槽、tags 槽（现 4）等 |
| 每分钟次数 | RPM（key_rate） | 每把 Key 每分钟请求上限（成员 5、手建 10），超出 429 |
| 冷却 | cooldown | 上游 429 后全站暂停出图的时间；或成员级限速（如 Explore 20 秒） |
| 结算 | settlement | 预留（reserved）→ 派发（dispatched）→ 落账（committed）/ 释放（released）/ 结果未知（uncertain）的状态机 |
| 结果未知 | uncertain | 上游没回话（超时/5xx）时的记账状态：额度先扣住，重启对账后恢复 |
| 免费额度 | legacy_free_images / V5 额度 | 成员每天的白嫖张数；Anlas 由站方账号代付 |
| 代付 | site_paid | 用我们账号的 Anlas 出图，成员不扣 |

## 模型与参数

| 术语 | 英文/代码 | 含义 |
|---|---|---|
| V4.5 | nai-diffusion-4-5-* | 当前主力模型族 |
| V5 | nai-diffusion-5-* | 新模型族，有权限开关（`v5`），额度单独算 |
| V5 Medium | -medium 后缀 | V5 的蒸馏档：锁 14 步 / Euler-a / 固定负面 |
| 角色提示词 | Character Prompts / char_captions | 画面里每个角色单独一段提示词（V4.5 最多 6，实测 3 个以上模型就开始丢人） |
| 负面提示词 | uc / negative_prompt | 不想要的内容 |
| Vibe | Vibe Transfer | 风格参考图（V4/V4.5 传**预编码**数据，经 /ai/encode-vibe） |
| 精确参考 | Precise Reference / Director Reference | V4.5 的角色/风格参考（PNG 原图） |
| 导演工具 | Director Tools | augment-image：Line Art / Colorize / Declutter / Emotion 等 |
| 四无请求 | blank generation | 正文 0 字 + 负面 0 字 + 无角色 + 无 Vibe/图生图材料 → 网关直接拒（上游必 500） |

## 反滥用

| 术语 | 英文/代码 | 含义 |
|---|---|---|
| 信号 | signal | 每日扫描产出的可疑证据，进后台「待审队列」，只排序不定罪 |
| 设备簇 | device_cluster | 同浏览器/同设备/同硬件指纹的账号并成一组（并查集） |
| 机器节拍 | machine_cadence（B4） | 同 Key 请求间隔 CV<0.05 → 脚本（影子运行中） |
| 簇覆盖 | cluster_coverage（B2） | 同簇账号跨 ≥20 小时段 + ≥3 个 /24 网段 → 共用（影子运行中） |
| 影子模式 | shadow mode | 新规则以 `status='shadow'` 入库不进队列，攒一周对比误报率 |
| JA4 | — | TLS 客户端指纹（P2 缓做，等影子数据） |

## 运维与工具

| 术语 | 英文/代码 | 含义 |
|---|---|---|
| CI | GitHub Actions | push 后自动构建 + 全量测试，绿了才允许部署 |
| 部署 / 上线 | deploy | `tools/deploy.sh`：下载 CI 产物 → 维护页 → 换容器 → 冒烟（不出图的自检）→ 摘维护页 |
| cutover | — | 部署里「旧容器切新容器」的那几秒 |
| 冒烟 | smoke | 上线后自动跑的只读检查清单（首页/接口/features），不消耗额度 |
| 快照测试 | snapshot test | 把函数输出 / 数据库行存成 `.jsonl` 逐字节比对；`UPDATE_SNAPSHOT=1` 重新生成 |
| 定时任务 | jobs | 网关内置的 9 个周期任务（滥用扫描 / 对账 / 快照 / 回收等），`job_last` 看健康 |
| `cargo test` / `clippy` | — | Rust 官方测试 / 静态检查器（相当于前端的 vitest / biome） |
| `grep -n` | — | 文本搜索，`-n` 显示行号；用来找"某符号还有没有人用" |
| `sleep 180` | — | 命令行等待，**参数是秒**（180=3 分钟、1800=30 分钟），多用于等 CI 跑完 |
| biome | — | 前端的 lint + 格式化工具（≈ cargo clippy + cargo fmt 合体），CI 门槛之一 |
| `sqlite3` | — | 直接读线上数据库的命令行（只读模式），查真实数据用 |
