# 构建与发布占用维护

本地工作树共享主仓库的 `target` 时，可以预览清理计划：

```bash
python3 tools/trim-build-cache.py --max-gib 8 --old-tests-days 2
```

确认预览后加 `--apply` 执行。它只选择旧 Rust 增量缓存和过期的带哈希测试可执行文件；保留最近的增量缓存、依赖库、当前普通二进制、源码与数据。目录必须有 Cargo 标记，符号链接不会被当成缓存删除；存在编译活动时拒绝执行。`--target` 可明确指定构建目录。

CI 的 Rust 测试与浏览器发布验收共用测试依赖缓存，浏览器任务只恢复、不重复保存。Clippy 继续使用独立缓存，避免只含检查元数据的缓存替代已编译依赖。Docker 中间依赖缓存保留，以免为少量磁盘空间换来每次完整重编译。

镜像构建写入 `OWL_BUILD_SHA` 和 OCI revision 标签，奶妹的只读状态接口直接报告生产版本。发布仍要求该提交全部 CI 成功；前端从同一镜像提取。成功发布后仅清理无标签且未被使用的镜像，以及一周前未用的构建层，保留运行和回滚镜像，不清理卷或业务数据。

GitHub 旧构建包清理应保留当前提交和可回滚提交。优先删除已被替代的镜像 / 运维二进制包、停用的缓存分组；源码、提交、运行日志和故障调查报告不属于清理对象。镜像传输包与运维二进制仍沿用现有到期策略，不缩短恢复窗口。
